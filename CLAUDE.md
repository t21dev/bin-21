# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Bin 21 is a modern, privacy-focused pastebin built with **TanStack Start** (on Vite + Nitro), TypeScript, and Tailwind CSS 4. It supports 150+ language syntax highlighting via Shiki, Markdown rendering with GFM, client-side AES-256-GCM encryption for private pastes, and stores paste content in Cloudflare R2 with metadata in SQLite via Drizzle ORM.

It deploys to Railway as a **single service**: the SQLite file lives on a mounted volume at `/data`. Because Railway forbids replicas on a service with a volume, the app is always single-instance, which is what makes in-memory rate limiting, in-process caches and the in-process janitor correct rather than merely convenient. It also means redeploys incur brief downtime and the app cannot scale horizontally.

It was ported from Next.js 16 to cut memory on Railway (billed per GB). Measured locally under identical load: ~93MB idle vs ~108MB, ~233MB vs ~262MB after 972 requests, 182ms vs 215ms average response.

## Commands

```bash
npm run dev          # Vite dev server (http://localhost:3000)
npm run build        # Production build -> .output/
npm start            # node --max-old-space-size=192 .output/server/index.mjs
npm run lint         # ESLint (flat config, typescript-eslint + react-hooks)
npm run db:generate  # Generate a SQL migration after editing lib/db/schema.ts
npm run db:push      # Push schema directly (dev shortcut, skips migration files)
```

`npx tsc --noEmit` type-checks. `src/routeTree.gen.ts` is generated by the router plugin on dev/build; commit it.

## Architecture

### Folder structure

- **`src/routes/`** - File routes. `$id.tsx` is the paste page; `$id_.raw.ts`, `$id_.opengraph-image.ts` etc. are server routes (the trailing `_` un-nests them from `$id`). `manifest[.]webmanifest.ts` escapes the dot.
- **`src/router.tsx`** - Router options: hover preloading, pending UI timing (300ms / min 500ms), View Transitions, default 404/error components.
- **`src/start.ts`** - Global request middleware: rate limiting and the `/admin` 404 gate (the old `proxy.ts`).
- **`src/server.ts`** - Server entry. Opens the DB (runs migrations) and starts the janitor at boot (the old `instrumentation.ts`).
- **`server/actions/`** - `createServerFn` server functions: the entry points for reads and mutations. Validate input (Zod), call services, return results. Called as `fn({ data })`.
- **`server/services/`** - Business logic: DB queries, R2 storage, stats. Actions call services, never the other way around.
- **`lib/`** - Shared utilities (DB client, Shiki highlighter, byte-capped LRU, rate limiter, janitor, admin auth, SEO helpers, OG image renderers, language list).
- **`lib/shiki-themes.ts`** - Client-safe theme list. Client components must import from here, never from `lib/shiki.ts` (server-only).
- **`components/`** - React components. `ui-kit.tsx` has the shared primitives (Segmented, SwitchRow, CopyButton, Panel, Dock).
- **`components/ui/`** - Vendored Recharts wrapper (Evil Charts), written against shadcn token names aliased in `src/styles.css`.
- **`types/`** - Shared TypeScript types.

### Data flow

1. User submits the paste form (client component)
2. `createPaste` server function (`server/actions/paste.actions.ts`) runs bot checks, validates with Zod
3. Service (`server/services/paste.service.ts`) generates the ID, uploads content to R2, saves metadata to SQLite
4. Client navigates to `/$id`; its loader calls `getPastePage`, which reads, highlights and records the view

### Key technical decisions

- **Paste content in Cloudflare R2**, metadata in SQLite. Content is never stored in the DB.
- **SQLite via `better-sqlite3`** (not `node:sqlite`: drizzle-kit can't generate migrations for it). WAL mode; migrations run on boot, safe because the volume guarantees a single process. In production `DATABASE_PATH` must be absolute.
- **Reads never mutate; views are recorded exactly once.** `readPaste`/`readPasteMetadata` are pure; `recordView` is the only view-counting write (it also deletes burn-after-read pastes on their 2nd view). The `/$id` loader passes `record: !preload` to `getPastePage`, because TanStack loaders also run on hover/focus **preloads**: recording there would burn pastes before the recipient opens them. The route sets `staleTime: 0`, `gcTime: 0`, `preloadStaleTime: 0`. **Verify view counts and burn-after-read after touching `src/routes/$id.tsx` or `getPastePage`.**
- **Rate limiting** is in-memory (`lib/rate-limit.ts`). Document requests are charged in `src/start.ts`; client-side navigations reach the paste through an RPC call to `/_serverFn/...`, so `getPastePage` charges those itself. Every POST (all server-function mutations) counts against the `create` budget, as Server Actions did under Next.
- **Client-side encryption** uses the Web Crypto API (AES-256-GCM + PBKDF2). The password never reaches the server. Components clear decrypted text and passwords on unmount.
- **Shiki** runs server-side with the **JavaScript regex engine, not Oniguruma WASM**: WASM memory never shrinks, so highlighter recycles leaked their high-water mark and RSS climbed for weeks. The highlighter caps resident languages (`MAX_RESIDENT_LANGUAGES`) and recycles past it. Output is identical for 327/328 bundled grammars (only `emacs-lisp` differs, which we don't offer).
- **Caches are byte-capped** (`lib/lru.ts`): 4MB of recently read R2 content (`storage.service.ts`, evicted on delete) and 4MB of highlighted HTML keyed by a hash of the code (`highlightCodeCached`). Keep budgets small; memory is the reason for this architecture.
- **Nitro `traceDeps`** keeps `shiki`, `better-sqlite3` and `@vercel/og` as real packages in `.output/server/node_modules`. Bundled, Shiki's ~300 grammars land in one 8MB module parsed on first use. Don't remove those entries.
- **`@vercel/og` is pinned to 0.11.x**: 1.0.x's Node ESM build does a CommonJS `require("fs")` and crashes.
- **Heap cap.** `npm start` runs Node with `--max-old-space-size=192`. It's in the start script, not `NODE_OPTIONS`, because the build needs more. The app runs on **Node**, not Bun: `better-sqlite3` is a Node native addon.
- **`<head>` tags** come from route `head()` functions. `HeadContent` de-duplicates `meta` by `name`, so the two `theme-color` tags are rendered directly in `__root.tsx`. Absolute OG URLs use `NEXT_PUBLIC_APP_URL`, inlined at build time (`vite.config.ts` `define`) so server and client render identical tags. The variable keeps its old name so Railway config doesn't change.
- **Expired pastes** are reclaimed by an in-process janitor (`lib/janitor.ts`, started from `src/server.ts`), gated behind `JANITOR_ENABLED`.
- **Static caching**: hashed `/assets/*` are immutable for a year (Nitro default); icons a week; `sw.js` is `no-cache` (route rules in `vite.config.ts`). Paste OG images are cached an hour.
- **Bot protection** uses honeypot fields and time-based detection (no CAPTCHA).
- **Dark mode** uses the `class` strategy via `next-themes` (framework-agnostic). Tailwind's `dark:` variant is bound to `.dark` in `src/styles.css`.
- **Path alias**: `@/*` maps to the project root.

### Environment variables

See `.env.example`. Key ones:
- `DATABASE_PATH` - SQLite file path (`/data/bin21.db` on Railway; defaults to `./.data/bin21.db`)
- `R2_*` - Cloudflare R2 credentials
- `NEXT_PUBLIC_APP_URL` - Public app URL for share links and OG tags (read at build time)
- `JANITOR_ENABLED` - set `true` only on the server; it deletes real R2 objects
- `ADMIN_TOKEN` - enables `/admin` analytics. Unset means the route 404s
- `PORT` - listen port (Nitro reads it)

### Design system ("Console", mint)

All tokens live in `src/styles.css` (`:root` light, `.dark` dark) and are mapped onto Tailwind via `@theme inline`, so `bg-primary`, `text-error` etc. resolve to the palette. Dark is pure black (`oklch(0% 0 0)`) for OLED; the accent is a calm mint-emerald (`--accent` for fills, `--accent-text` for text, which is darker in light mode for contrast). Fonts: Geist + Geist Mono (self-hosted via `@fontsource-variable`). Icons: `lucide-react`.

Layout: on md+ a page is an editor/content card plus a sticky options rail (`Panel`). Below md the rail becomes a bottom sheet and actions live in a fixed bottom `Dock` (48px targets, safe-area aware); `body:has([data-dock]) .site-footer` keeps the footer clear of it. Code soft-wraps with hanging line numbers on phones. The paste card and rail carry `vt-card` / `vt-panel` view-transition names so routes morph rather than cut. Respect `prefers-reduced-motion` (handled globally).
